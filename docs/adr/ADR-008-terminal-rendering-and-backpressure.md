# ADR-008：终端渲染与背压策略

- 状态：已接受（M1）
- 日期：2026-10-21
- 关联：`docs/architecture.md` §7、§18；ADR-001、ADR-002

## 背景

终端是最高频、最敏感的界面：

- 必须完整解析 ANSI/真彩色/鼠标上报/OSC 序列，不能丢字节；
- 远端可能瞬间输出数百 MB（`cat` 大文件、`yes`、编译日志），不能阻塞 UI 或打爆内存；
- 多标签/分屏并存，WebGL 上下文数量有限；
- WebView 差异（WebKitGTK、WebView2）导致 GPU 行为不一致；
- 100+ 标签时不能为每个标签保留昂贵渲染资源。

需要同时决定：渲染器、数据通道、流控与降级策略。

## 选项（渲染）

| 选项 | 优点 | 缺点 |
|---|---|---|
| xterm.js + WebGL 插件 | 生态成熟、真彩色、性能好 | 每实例一个 WebGL 上下文；上下文丢失需处理 |
| xterm.js + canvas | 稳定、上下文少 | 高吞吐下 CPU 更高 |
| xterm.js + DOM | 兼容性最好 | 大量行时性能差 |
| 自研 Rust/GPU 终端 | 性能上限高 | 解析器/选择/IME/无障碍成本巨大，不可接受 |

## 选项（背压）

| 选项 | 说明 | 问题 |
|---|---|---|
| 无限制转发 | 后端读到就发 | 内存爆炸、IPC 堵塞、UI 卡死 |
| 丢弃旧帧 | 只保留最新 | 终端字节流会被破坏（转义序列截断） |
| 固定速率限流 | 定时发送 | 无法感知前端消费能力，仍会积压 |
| 信用窗口（credit） | 前端按消费量授予额度 | 需要 ACK 往返，但语义正确（本项目选择）；极端持续过载时另设硬上限 |

## 决策

1. **渲染**：`@xterm/xterm` + `@xterm/addon-webgl`（可见标签）+ `fit`/`search`/`web-links`；WebGL 不可用或上下文丢失时**自动降级 canvas**；DOM 渲染仅作为最后的兼容兜底（可通过设置强制）。
2. **顶层约束**：最多 8 个"活跃 WebGL 渲染"标签；超出或标签隐藏时释放其 WebGL 上下文，切回 canvas/DOM。
3. **数据通道**：每标签独立 `Channel<ArrayBuffer>`，二进制帧（tag + u32 length + payload），通知类走同通道的低频 tag；退出/错误走事件。
4. **信用窗口（正常路径，不丢字节）**：
   - 初始信用 256 KiB；
   - 前端在 xterm `write` 回调后按 ≥ 32 KiB 增量 `terminal_ack`；
   - 后端未确认字节 > 512 KiB → 暂停读取 SSH/PTY；
   - SSH 窗口机制把压力自然传导到远端，PTY 暂停读取会阻塞子进程。
5. **硬上限（TERM-020）**：单标签待发送 > 8 MiB 且持续 > 5 s → 丢弃最旧数据至 4 MiB，发一次 `terminal://notice{kind:"flow", dropped_bytes}` 并记录指标/日志；输入路径不受影响（Ctrl+C 可达）。
6. **合并写**：Reader 攒 16 KiB 或 8 ms 再发一帧，单帧 ≤ 64 KiB；隐藏标签合并阈值提高到 32 KiB。
7. **回滚缓冲**：默认 10 000 行，范围 1 000–100 000（TERM-006）；超出由 xterm 裁剪最早行；可选 `SerializeAddon` 快照用于标签恢复（M3）。
8. **输入路径**：键盘事件 4 ms 微批，走原始字节 `terminal_write`；粘贴二进制安全，按 64 KiB 分片。

## 理由

1. 终端字节流是**有序**的：正常路径必须完整（信用窗口保证）；仅在 TERM-020 的极端持续过载下丢弃最旧输出并显式提示，避免 UI 冻结与内存无限增长。
2. 合并写把 IPC 调用量降低一个数量级（16 KiB/帧），显著减少 WebView↔Rust 序列化成本，同时保持交互延迟（8 ms 上限）。
3. WebGL 上下文是稀缺资源，按"可见性 + 上限"分配，避免 20 个标签时 GPU 驱动崩溃或显存膨胀。
4. 自动降级保证在虚拟机、远程桌面、软件渲染（SwiftShader/llvmpipe）等环境下仍可工作。

## 后果

**正面**

- 远端洪泛时内存有硬上界（正常 ≤ 512 KiB 未确认 + 8 MiB 待发送上限 + 回滚缓冲）。
- 输入回显不受输出洪泛影响（输入走独立命令，不受信用窗口限制）。
- 降级路径明确，WebView 差异可控。

**负面与缓解**

| 后果 | 缓解 |
|---|---|
| 信用 ACK 增加 IPC 往返 | ACK 批量（≥ 32 KiB），频率极低；ACK 命令极轻量 |
| 前端 `write` 回调可能延迟（渲染忙碌） | 限制单次 `write` 块 ≤ 64 KiB，避免长任务；隐藏标签不做渲染 |
| WebGL 上下文丢失导致闪烁 | 监听 `webglcontextlost`，自动重建或降级 canvas，保留缓冲 |
| 高回滚行数导致内存超目标 | 默认 10 000 行；按标签数与内存压力动态建议上限；设置中显示估算占用 |
| 远端 `cat` 大文件时吞吐受 8 ms 合并影响 | 实测目标 ≥ 5 MB/s/标签；必要时自适应阈值（32 KiB / 4 ms） |
| 同步滚动/多执行带来额外写放大 | 多执行走独立批量命令，一次写入所有目标，不逐标签 IPC |

## 实现约束

1. 帧解析必须容忍拆包/粘包（TCP/Channel 语义），按 `length` 严格切分。
2. 后端不得在持锁状态下写 Channel；WriterTask 串行发送。
3. 关闭标签时：先停止读取 → 关闭通道 → 释放 WebGL → drop xterm；顺序不可颠倒。
4. 指标：`term_bytes_total`、`term_backpressure_seconds_total`、`term_credit_outstanding_bytes`、`term_frame_size_bytes`。
5. 基准测试：`tests/perf/terminal_throughput.rs`（Docker sshd + 50 MB base64 输出）与前端长任务采样；正常背压路径丢失字节数必须为 0，硬上限路径必须记录 `dropped_bytes`。

## 验证与退出条件

- TERM-020：20 MB/s 连续 60 s，UI 可交互、内存增长 ≤ 200 MB、丢弃提示出现一次、Ctrl+C 可达。
- 200 MB 连续输出：输入回显 p95 ≤ 50 ms、无解析错误。
- 20 个标签（其中 2 个可见）：无 WebGL 上下文耗尽，切换标签 < 100 ms。
- 弱网（`tc netem` 丢包 5%、延迟 200 ms）：重连后终端状态可见、无重复/丢失字节导致的乱码。
- 若 WebGL 在某平台持续不可用，仅降级渲染器，不改变数据通道与背压设计。
