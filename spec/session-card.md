## 1. 视图卡（Session Card）核心模型

### 1.1 基本定义与绑定原则

1. **一连接 = 一视图卡（Strict 1:1 Binding）**：
   - 视图卡是用户操作远程主机或本地设备的顶层交互与状态载体。
   - 每发起一次远程会话（如 SSH 连接）或外设连接（如 Serial 串口），系统在工作区创建一张唯一的 **视图卡（Session Card）**。
   - 视图卡生命周期与底层核心连接进程/会话句柄 **一一严格绑定**，同生共死。
   - 同一主机可建立多张视图卡（多个完全隔离的独立会话），互不干扰。
2. **底层单连接通道复用（Channel Multiplexing）**：
   - 对于 SSH 协议的视图卡，卡内的 **命令模式（终端）** 与 **视图模式（SFTP 文件视图）** 必须共用**同一条底层 SSH 传输层连接（Single TCP Connection）**；
   - 严禁为了文件浏览而在后台发起第二次 SSH 握手或重复输入/解密密码凭据；
   - SSH 连接成功时，主 Shell PTY 通道与 SFTP 子系统（Subsystem `sftp`）通道由核心层统一编排建立。
3. **特化协议适配（Serial 串口卡）**：
   - 当连接协议为 `Protocol::Serial` 时，卡片只启用 **命令模式**，视图模式切换控件处于隐藏或禁用置灰状态。

## 2. 状态机契约（Session Card State Machine）

视图卡的状态必须完全由核心编排层（`SessionCardManager` / `app-core`）权威维护，前端 UI 只订阅状态事件并进行纯渲染，**严禁 UI 自行根据部分网络报错推断状态**。

### 2.1 状态定义

```
                  ┌──────────────┐
                  │ Connecting   │
                  └──────┬───────┘
                         │ 握手成功
                         ▼
                  ┌──────────────┐
          ┌──────►│  Connected   │◄──────────────┐
          │       └──────┬───────┘               │
          │              │ 意外断网/拔出          │ 重连成功
  重连成功 │              ▼                       │
          │       ┌──────────────┐               │
          │       │ Disconnected │               │
          │       └──────┬───────┘               │
          │              │ 用户点击重连 / 自动重连 │
          │              ▼                       │
          └───────┴─ Reconnecting ───────────────┘
                         │
                         │ 达到最大重试 / 用户主动放弃
                         ▼
                  ┌──────────────┐
                  │    Closed    │ (从 UI 移除并完全释放资源)
                  └──────────────┘
```

| 状态枚举（`CardState`） | 触发条件 | UI 表现 | 行为约束 |
|---|---|---|---|
| `Connecting` | 用户点击连接或新建会话 | 标签栏显示加载 Spinner，卡片内展示连接中骨架屏与握手阶段提示 | 禁用模式切换与文件操作 |
| `Connected` | 传输层握手、凭据校验、通道打开全部成功 | 标签显示绿色在线指示灯，命令模式终端就绪，视图模式 SFTP 根目录就绪 | 允许自由双模式切换、输入、上传下载 |
| `Disconnected` | 网络超时、连接被对端重置（RST）、USB 串口被拔出 | 标签显示黄色/灰色断开指示灯，卡片主体覆盖半透明统一断线浮层（显示断线原因与“一键重连”按钮） | 暂停所有正在进行的传输任务，保留终端历史与目录缓存，不关闭卡片 |
| `Reconnecting` | 用户点击一键重连，或配置了自动重试退避定时器触发 | 断线浮层切换为重试中动效（如“正在重新连接 (第 2/5 次)...”） | 后台异步发起重连握手，不阻塞用户查看已缓冲的内容 |
| `Closed` | 用户点击卡片右上角关闭按钮（或快捷键关闭） | 卡片从标签栏与视口平滑淡出并销毁 | 立即向底层发送断开请求，销毁所有子通道、中止传输任务、清理临时编辑文件 |

### 2.2 异常断开与双模式同步恢复契约

1. **断开时的统一行为**：
   - 底层探测到底层连接断开时，立即广播 `card://state-changed { card_id, state: Disconnected, reason }`。
   - 命令模式终端与视图模式文件管理器**同步进入禁用状态**。
   - 该卡归属的所有正在传输的 SFTP 任务自动转为 `Paused`（暂停）状态，并记录当前已完成的断点偏移量，严禁直接判定为失败并删除任务！
2. **重连成功后的双模式恢复**：
   - 重连成功后，核心层发布 `card://state-changed { card_id, state: Connected }`。
   - 命令模式终端打印系统提示行（如 `\r\n[OpenShell] Session reconnected successfully.\r\n`），光标恢复；
   - 视图模式自动在后台向 SFTP 子系统发起一次静默刷新（`refresh_dir`），更新当前目录状态；
   - 弹出通知栏提示：“会话已恢复。存在 2 个未完成的传输任务，是否继续传输？”，用户可一键恢复队列。

## 3. 命令模式与视图模式切换规格

### 3.1 切换控件与快捷键体系

1. **切换器位置与视觉规范**：
   - 视图卡顶部右上角（或紧邻会话标题右侧）提供一体化双联分段控件（Segmented Switcher）：
     - `命令（Terminal）`：带终端命令行图标（`>_`）。
     - `视图（SFTP）`：带文件夹/云端传输图标。
     - 切换时有流畅的滑动或淡入淡出动效。
2. **快捷键规范**：
   - 全局支持 `Ctrl + Shift + Tab`（macOS 为 `Cmd + Shift + Tab`）在当前激活卡的命令模式与视图模式之间即时往返切换。
   - 快捷键可由用户在首选项中重新定义。

### 3.2 模式切换时的“无损保持”规格（Critical）

1. **终端模式后台静默保活**：
   - 当用户切到**视图模式**时：
     - 后台 SSH Shell PTY 通道**绝不断开**；
     - 远端持续输出的内容（如持续运行的构建脚本、top 监控等）由核心层与前端 xterm 虚拟视口**继续在内存中缓冲**；
     - 禁止丢弃任何输出流数据；
   - 当用户切回**命令模式**时：
     - 终端窗口立即呈现，且已无缝追加了在后台期间接收到的全部输出；
     - 终端此前的光标位置、滚动条位置、文字选中区域 100% 保持，无闪烁，无需重新绘制终端。
2. **视图模式状态独立保持**：
   - 当用户从视图模式切到命令模式、再切回视图模式时：
     - 必须完整恢复之前的浏览路径（如 `/var/log/nginx/`）；
     - 必须保留文件列表的排序设置（如按修改时间降序）；
     - 必须保留此前选中的文件集合与滚动条视口偏移；
     - 无需每次切回都全量重新从服务器拉取目录，优先利用缓存渲染，并在后台异步校验更新。

### 3.3 终端当前目录跟随增强（OSC 7 CWD Integration，可选）

- 当在命令模式下工作时，OpenShell 自动解析终端 PTY 流中的 `OSC 7` 转义序列（形如 `\x1b]7;file://hostname/current/path\x1b\\` 或 BEL 终止符）；
- 在卡片顶栏或视图模式界面中，提供一个“跟随终端当前目录”快捷跳转按钮；
- 用户一键即可直接将 SFTP 视图导航到终端当前正处于的目录，极大提升运维排障效率。

## 4. 多会话与多卡片组织规格

1. **标签栏组织**：
   - 视图卡在工作区主区域以多标签（Tabs）形式陈列；
   - 支持鼠标拖拽标签进行顺序重排；
   - 标签右键菜单提供：`复制会话（在新卡片打开）`、`重命名卡片`、`重新连接`、`关闭卡片`、`关闭其他卡片`。
2. **关闭安全保护**：
   - 当用户点击关闭视图卡时，若该卡名下存在正在运行的 SFTP 传输任务或活动的编辑锁定：
     - 必须弹出阻塞模态框：“当前会话有 2 个文件正在传输中，关闭卡片将中止传输。确定关闭吗？”
     - 选项：`取消` / `中止并关闭`。
